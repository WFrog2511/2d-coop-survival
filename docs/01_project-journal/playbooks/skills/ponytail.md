# Ponytail最小実装

実装、修正、リファクタリング、依存選定、過剰設計レビューで使う。影響範囲を理解した後、次の順に最初に成立する方法を選ぶ。

1. そもそも不要なら作らない。
2. リポジトリ内の既存コード、Skill、hook、toolを再利用する。
3. 標準ライブラリを使う。
4. ブラウザ、DB、フレームワーク、OSなどの標準機能を使う。
5. 導入済み依存を使う。
6. 要求を満たす最小の直接実装にする。

最小化のために、認証・認可、信頼境界の入力検証、データ損失防止、アクセシビリティ、監査、必須エラー処理、合意済み要件を削らない。非自明なロジックには小さな実行可能チェックを残し、リポジトリの品質ゲートを優先する。

意図的な簡略化に上限がある場合だけ、コードコメントまたはIssueへ `ponytail: <上限>, revisit when <再検討条件>` と記録する。完了時は、採用した最小案、対象外、追加を再検討する具体的条件を示す。

由来、固定バージョン、公式完全版との差は [Ponytail導入ガイド](../ponytail.md) を参照する。
