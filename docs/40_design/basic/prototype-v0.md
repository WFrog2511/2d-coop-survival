# prototype-v0 基本設計

## 責務

- `src/main.ts`: Phaser Scene、固定アリーナ、入力、描画、物理衝突、弾プール、DOM HUD、敗北と再挑戦を担当する。
- `src/rules.ts`: HPの減算・0へのclamp・敵撃破判定・初期戦闘状態を純粋関数で担当する。
- `tests/rules.test.ts`: HPと再挑戦状態の境界を検証する。
- `e2e/prototype.spec.ts`: ブラウザ上の敗北から再挑戦までの経路を検証する。

## データフロー

キーボード・ポインター入力を`Arena`が受け、物理ボディの速度または弾へ変換する。衝突時は弾を先に無効化してから`rules.ts`の関数へ状態を渡す。状態更新後にHUDを更新する。プレイヤー敗北時は物理を停止し、再挑戦時はScene内部の可変状態と物理ボディを初期化する。

## 失敗時とリセット

HUD要素がない場合は起動時に明示的に失敗する。弾プールが上限に達した場合は追加発射せず、画面外または衝突済みの弾を再利用する。敵の再出現タイマーは再挑戦時に解除するため、旧タイマーが初期化後の敵HPや位置を書き換えない。

## Ponytailの境界

単一クライアント・敵1体・Canvas生成テクスチャ・Phaser Arcade Physicsだけを使う。外部アセット、状態管理ライブラリ、ネットワーク、抽象化レイヤーは追加しない。複数人同期、複数武器、永続化を着手する時点で、共有ゲームデータまたはサーバー構成を再検討する。
